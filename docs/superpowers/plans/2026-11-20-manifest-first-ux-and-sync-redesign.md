# 密诀 (MantraKey) 清单优先架构与首屏交互重构设计实现方案

> **文档状态**：待评审 / 准备实施
> **设计版本**：v2.0 (Manifest-First & Multi-Account Rotation)
> **涉及端形态**：Chrome MV3 浏览器扩展端、Android 移动端、PC 桌面端 HUD、Rust 核心库

---

## 一、背景与设计目标

### 1.1 现状痛点诊断
1. **首屏“强制全屏阻拦”反人类**：目前插件一打开就强迫用户输入“唯一主口令”，用户无法预先感知当前网站存了哪些账号、不知道该输入哪个口令、无法直接查看或管理清单，严重脱离主流密码管理器（1Password / Bitwarden）的用户心智；
2. **口令灵活性受限**：原设计过度假设“全网必须死板共用一个全局主口令”，而忽视了用户“不同等级网站可能使用不同口令组合”的自由度与现实习惯；
3. **改密交互链路长**：当用户在网站上修改密码时，缺乏一键轮换、双框自动填充（新密码+确认密码）并联动清单自增版本的闭环；
4. **离线数据迁移缺失**：缺乏本地直接导出/导入备份文件（JSON / 加密 .mkey）的通道，以及导入时的冲突解决决策界面。

### 1.2 重构目标
- **清单优先（Manifest-First）**：打开插件立即呈现当前网站已存账号、快速录入区与全局站点清单；
- **口令按需唤起（On-Demand Mantra）**：不阻拦首屏浏览与录入，仅在点击“填充”、“生成”或“查看”时才优雅唤起口令计算；
- **口令自由度**：主口令依然绝不落盘；工具支持用户为不同网站输入不同口令进行派生，若用户习惯输入同一口令也能 100% 顺畅工作；
- **一键改密轮换（One-Click Rotation）**：点击一次即完成“版本+1、现场派生、网页双框一键填入、清单版本持久化更新”；
- **双轨同步与三档冲突裁决**：支持 WebDAV 自动同步与本地离线导入导出；导入时提供“智能合并 / 仅新增 / 完全覆盖”三档明确选择，底层 AES-GCM 签名防错熔断。

## 二、数据契约模型设计

### 2.1 记录清单（Manifest）Schema
清单中**仅记录公开的派生元数据，绝对不存任何主口令明文**：

```typescript
export interface AccountEntry {
  username: string;          // 账号名/邮箱
  version: number;           // 密码轮换版本号 (默认 1, 改密自增)
  rulePreset: RulePreset;    // 密码规则 ('standard-16' | 'secure-20' | 'super-32' | 'pin-6' | ...)
  tag?: string;              // 分类标签 ('Personal' | 'Work' | 'Finance' | ...)
  updatedAt: number;         // 毫秒级时间戳 (用于 LWW 冲突合并)
  isDeleted?: boolean;       // 软删除墓碑标记 (防止同步被旧端复活)
}

export interface DomainEntry {
  domain: string;            // 规范化顶级域名 (如 github.com)
  displayName?: string;      // 网站别名 (如 GitHub)
  category?: string;         // 站点分类
  accounts: AccountEntry[];  // 该网站下的账号列表
  updatedAt: number;
}

export interface MantraManifest {
  schemaVersion: number;     // 协议版本 (如 2)
  updatedAt: number;         // 清单总时间戳
  domains: Record<string, DomainEntry>; // Key 为 domain (全小写)
}
```

### 2.2 口令与派生模式解耦设计
- **计算逻辑**：
  $$\text{Site Password} = \text{Derive}(\text{Mantra}, \text{Domain}, \text{Username}, \text{Version}, \text{Rule})$$
- **行为约定**：
  - 工具不对“主口令”施加硬性全网全局绑定。
  - 用户可以习惯性地对所有网站输入同一口令（最省心模式）；
  - 用户也可以对重要网站（如银行）输入专有的安全口令。
  - 插件提供 **“当前会话口令缓存（15分钟 TTL，仅驻留内存）”**：只要用户当前解锁了会话，后续填充默认复用该口令；若遇到特殊网站，用户可直接在卡片上点击“使用独立口令计算”，随心所欲。

## 三、插件首屏交互重构（Manifest-First）

### 3.1 视图状态机拆解

```text
┌──────────────────────────────────────────────────────────┐
│ 密诀 MantraKey          [ 🌐 同步 ]  [ 📁 清单 ] [ 🔒 会话 ] │
├──────────────────────────────────────────────────────────┤
│ 🌐 当前站点: github.com                         [切换]   │
├──────────────────────────────────────────────────────────┤
│ 📋 本站已存账号 (1)                                      │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 👤 user@domain.com            [Work] [v1] [ ✏️ ] [ 🗑️ ] │ │
│ │ 密码: ••••••••••••••••         [ 👁️ 显示 ] [ ⚡ 填充 ] │ │
│ │                                                      │ │
│ │ [ 🔄 轮换新密码 (升级为 v2 并填入网页) ]               │ │
│ └──────────────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────┤
│ ⚡ 快捷录入新账号                                         │
│ 用户名: [ admin@github.com      ]                      │
│ 规格:   [ 16位标准 (字母+数字+符号) ▼ ]   版本: [ - 1 + ] │
│ 密码:   ••••••••••••••••                               │
│ [ 💾 保存并填充到网页 ]                                 │
└──────────────────────────────────────────────────────────┘
```

1. **首屏无阻拦展示**：
   - 用户打开插件，**第一眼看到的是当前网站已有的账号**，以及快速录入新账号的表单；
   - 彻底移除一打开就挡住全屏的 `view-locked`。
2. **按需计算与口令输入（On-Demand Mantra Sheet）**：
   - 若内存会话已激活（TTL > 0）：点击“⚡ 填充”或“👁️ 显示”直接出结果，秒级响应；
   - 若内存会话未激活（未输入口令）：
     - 点击“⚡ 填充”或“👁️ 显示”时，底部**平滑向上滑出一个小巧精致的“口令输入抽屉（Mantra Sheet）”**；
     - 用户输入口令，按下回车或点击确认：
       - 立即计算并完成填充；
       - 同时自动激活 15 分钟内存会话（用户后续在其他网页直接免输口令）；
       - 抽屉自动缩回，绝不遮挡核心内容。

## 四、改密与编辑交互设计（核心求“方便”）

### 4.1 场景 A：网页修改密码（一键密码轮换）
用户打开网站的“修改密码”页面时：
1. 打开密诀插件，识别到当前账号 `v1`；
2. 点击账号卡片上的 **`🔄 轮换新密码`** 按钮：
   - 检查会话口令（若未输入则唤起抽屉输入）；
   - 系统自动执行版本自增：$\text{version} = 2$；
   - 现场即刻派生出第 2 代密码；
   - **自动化 DOM 填充**：
     - 若当前网页有“旧密码/当前密码”输入框，自动填入第 1 代密码；
     - 自动检测并填入“新密码框”与“确认新密码框”；
   - **清单同步落盘**：该账号在清单中的 `version` 自动更新为 `2`，`updatedAt` 刷新为当前毫秒；
   - 页面弹出反馈：`✅ 已成功生成第 2 代密码并完成填充！`
3. **全流程用户只点一次按钮，无需记忆、无需拷贝粘贴**。

### 4.2 场景 B：手动编辑条目
- 点击账号卡片右上角的 `✏️` 图标；
- 原地展开编辑面板，允许用户：
  - 修改用户名；
  - 手动调整版本号（支持回退或跳跃）；
  - 切换密码规格（如 16位标准、20位高强、纯数字 PIN 码）；
  - 修改分类标签（Personal / Work 等）；
  - 点击 `🗑️ 删除账号`（带确认弹窗与墓碑标记）。

## 五、本地导入导出与冲突解决策略

### 5.1 导出通道
在顶部“清单管理”或“同步设置”中提供两种导出选项：
1. **加密备份文件 (`.mkey`) - 推荐**：
   - 提示输入主口令（或导出加密密码）；
   - 使用 `PBKDF2 (100,000次)` + `AES-256-GCM` 进行信封封装；
   - 导出为标准的 `mantra_backup.mkey` 二进制文件，第三方拿到此文件无法偷窥任何站点元数据。
2. **明文导出文件 (`.json`)**：
   - 导出人类可读的标准 JSON 文本清单（弹出安全警示：请妥善保管明文）。

### 5.2 导入通道与三档冲突解决方案
用户点击 `📥 导入清单` 并选择文件后：
- 若为 `.mkey` 文件：先提示输入解密口令。若口令错误，AES-256-GCM 标签校验失败，**直接报错熔断，绝不污染本地数据**；
- 若解密成功，系统比对导入清单与本地现有清单：
  - 若**无重合**（全是新网站）：自动无缝合入，提示 `成功导入 X 个站点，Y 个账号`；
  - 若**存在重合**（某些域名和账号本地已存在）：弹出冲突决策弹窗：
    1. **智能增量合并 (Smart CRDT Merge - 默认推荐)**：
       - 新增站点直接吸纳；
       - 重合账号：`version` 取大值（保留更新的改密），规则属性以 `updatedAt` 最新者胜出；
    2. **仅导入新增条目 (Keep Local on Conflict)**：
       - 本地已有的账号一律维持现状，仅追加本地完全没有的站点；
    3. **完全覆盖本地 (Force Overwrite)**：
       - 彻底清空本地清单，完全以导入文件的状态为准。
